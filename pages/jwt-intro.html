Введение в JWT (JSON Web Token)

В предыдущей главе мы разобрали классический подход к аутентификации через сессии и cookies. Этот метод хорошо работает для традиционных серверных приложений, но в эпоху мобильных приложений, одностраничных сайтов (SPA) и микросервисной архитектуры он начинает показывать свои ограничения. На смену сессиям пришёл новый стандарт — JWT.

JSON Web Token (произносится как «джот») за последние несколько лет стал де-факто стандартом для передачи данных между сторонами в вебе. Его используют крупнейшие компании: Google, Microsoft, Amazon, а также большинство современных API. Разберёмся, что это такое и почему JWT стал так популярен.

Что такое JWT?

JWT (JSON Web Token) — это открытый стандарт (RFC 7519), который определяет компактный и самодостаточный способ безопасной передачи информации между сторонами в виде JSON-объекта. Эта информация может быть проверена и доверена, потому что она имеет цифровую подпись.

Простыми словами: JWT — это небольшой «билет» или «пропуск», который сервер выдаёт пользователю после успешной аутентификации. Этот билет содержит в себе всю необходимую информацию о пользователе и защищён от подделки с помощью криптографической подписи. Серверу не нужно хранить никаких данных о сессии — вся информация уже внутри самого токена.

Зачем нужен JWT?

JWT решает несколько ключевых задач в современной веб-разработке:

  • Аутентификация без состояния (stateless) — серверу не нужно хранить информацию о сессиях пользователей. Вся необходимая информация содержится в самом токене. Это значительно упрощает масштабирование приложений.
  • Обмен информацией между сервисами — JWT идеально подходит для микросервисной архитектуры, где несколько независимых сервисов должны доверять друг другу. Один сервис может выпустить токен, а другой — проверить его без обращения к центральному хранилищу.
  • Одноразовые токены — JWT часто используется для одноразовых действий: подтверждение регистрации по email, сброс пароля, приглашение в систему.
  • Авторизация в API — при работе с REST API или GraphQL JWT передаётся в заголовке каждого запроса, позволяя серверу идентифицировать пользователя.

Преимущества JWT перед сессиями

Переход от сессий к JWT даёт разработчикам ряд существенных преимуществ:

  • Масштабируемость — поскольку сервер не хранит состояние, вы можете добавить сколько угодно серверов за балансировщиком нагрузки, и все они будут работать с одними и теми же токенами. Не нужно синхронизировать сессии между серверами.
  • Кросс-доменность (CORS) — JWT легко передаётся между разными доменами. Это критически важно, когда фронтенд и бэкенд размещены на разных доменах, или когда нужно предоставить доступ стороннему приложению.
  • Производительность — проверка JWT происходит локально на сервере (проверка подписи), без обращения к базе данных или хранилищу сессий. Это быстрее, чем поиск сессии по Session ID.
  • Поддержка мобильных приложений — мобильные приложения не работают с cookies так же удобно, как браузеры. JWT легко сохраняется в локальном хранилище приложения и отправляется в заголовке запроса.
  • Децентрализация — токен может быть выпущен одним сервисом (например, сервисом аутентификации), а проверен другим (например, сервисом оплаты). Им не нужно иметь общую базу сессий.
Недостатки JWT, о которых важно знать:
  • Невозможность отзыва токена «на лету» — если токен украден, вы не можете просто удалить его на сервере, как сессию. Токен будет действителен до истечения срока его жизни.
  • Размер токена — JWT больше, чем Session ID, потому что содержит всю информацию о пользователе.
  • Хранение чувствительных данных — Payload токена только закодирован (base64), но не зашифрован. Любой может декодировать его и увидеть содержимое.
  • Сложность реализации — по сравнению с сессиями, работа с JWT требует понимания криптографии, сроков жизни токенов, механизмов обновления.

Как выглядит JWT?

Внешне JWT — это длинная строка, состоящая из трёх частей, разделённых точками. Каждая часть закодирована в формате Base64Url. Пример токена:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

На первый взгляд это просто набор символов, но на самом деле строка имеет чёткую структуру. В следующей главе мы подробно разберём, из каких частей состоит JWT и что хранится в каждой из них.

Где используется JWT?

JWT применяется в самых разных сценариях современной разработки:

  • Single Page Applications (SPA) — React, Vue, Angular приложения, которые общаются с сервером через API.
  • Мобильные приложения — iOS и Android приложения, которые хранят токен в безопасном хранилище устройства.
  • Микросервисы — передача информации о пользователе между независимыми сервисами.
  • SSO (Single Sign-On) — единый вход в несколько приложений с одной аутентификацией.
  • Подтверждение действий — ссылки для сброса пароля, подтверждения email, приглашения в систему.

Краткое резюме

JWT — это современный стандарт для безопасной передачи информации между сторонами. Он решает проблемы масштабирования, кросс-доменных запросов и работы с мобильными приложениями, которые были у классических сессий. Однако JWT не является «серебряной пулей» — у него есть свои недостатки, которые нужно учитывать при проектировании системы безопасности.
